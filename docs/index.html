ironveil scan ./my-project --llm --llm-max-files 10 --output html

📄 Technical Whitepaper

Hybrid AI-Powered Security & Code Quality Analysis

1. Executive Summary

Software vulnerabilities cost organisations billions annually. Traditional static analysis tools (SAST) are fast and reliable but limited to pattern matching — they cannot reason about business logic, contextual security flaws, or architectural anti-patterns. Large Language Models (LLMs) offer deep semantic understanding but are slower, more expensive, and prone to false positives.

IronVeil presents a hybrid code scanning architecture that combines the speed and precision of traditional SAST tools with the contextual reasoning capabilities of LLMs. The result is a scanning system that finds 40–80% more real issues than traditional tools alone, while keeping false positives low and costs manageable.

2. The Problem

Limitations of Traditional SAST

Tools like Snyk, TruffleHog, Semgrep, and linters operate on pattern matching and rule engines. They excel at detecting known CVEs, finding hardcoded secrets, and enforcing coding standards.

They fundamentally cannot detect:

  • Business logic flaws (e.g., negative payment amounts)
  • Authentication bypass due to flawed control flow
  • Race conditions in concurrent transaction processing
  • Architectural problems (tight coupling, missing abstraction layers)
  • Context-dependent vulnerabilities requiring understanding of developer intent

Limitations of Pure LLM Analysis

LLMs provide semantic code understanding but have drawbacks: speed (minutes vs seconds), token-based cost, hallucination risk, and non-deterministic results.

3. Architecture

IronVeil runs a four-phase pipeline:

Phase 1: Traditional Scan (2–3 min)
  ├── Clone repository
  ├── Detect language(s)
  ├── Run Snyk, TruffleHog, Semgrep, Bandit, linters
  └── Generate baseline findings

Phase 2: Risk Prioritisation (< 1 min)
  ├── Analyse repository structure
  ├── Score files by risk level (high/medium/low)
  └── Select top N high-risk files

Phase 3: LLM Analysis (5–15 min)
  ├── Security analysis of priority files
  ├── Logic and edge case analysis
  ├── Architecture assessment
  └── Generate findings with fix suggestions

Phase 4: Result Fusion (< 1 min)
  ├── Cross-reference traditional + LLM findings
  ├── Remove duplicates, recalculate severity
  └── Generate prioritised report

9. CI/CD Integration

# GitHub Actions example
name: Security Scan
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - run: pip install ironveil[all]
      - run: ironveil scan ./ --output json
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}

10. Conclusion

The hybrid scanning approach delivers the best of both worlds — the speed and reliability of traditional SAST tools combined with the deep understanding of LLM-powered analysis. By intelligently orchestrating both approaches and focusing LLM resources only on high-risk files, IronVeil achieves:

  • 40–80% more real vulnerabilities found than traditional tools alone
  • Low false positive rates through cross-validation
  • Actionable remediation with code-level fix suggestions
  • Cost-effective operation suitable for continuous deployment pipelines

This architecture represents a practical, production-ready approach to AI-augmented security scanning that can be deployed today on commodity hardware.
